# 产业链风险传播与数据契约

工行杯个人参赛项目中，能够独立运行的路径传播、财务口径和提交契约核心。

这个仓库关注三个问题：**风险沿什么路径传导、参与计算的数值是否口径一致、输入和输出能否被证据约束。**

| 模块 | 行为 | 关键边界 |
| --- | --- | --- |
| `supply_chain.py` | 沿有向图枚举简单路径、计算边权连乘、保留出处和估计标记 | 最强路径暴露不是违约概率，也不是 Leontief 总效应 |
| `financial_metrics.py` | 校验 EBIT 组成项、利息保障倍数与流动性披露口径 | 缺失不等于零；历史口径迁移必须明确启用 |
| `submission_contract.py` | 严格解析版本化契约，约束字段、路径、日期与来源哈希 | 重复 JSON 字段、来源不一致和未确认契约显式失败 |
| `missing_values.py` | 统一缺失文本标记 | 只归一化缺失表达，不将其解释为无风险 |

## 快速运行

Python 3.10 或更新版本，运行依赖只有 NetworkX。

```sh
python -m venv .venv
```

Windows：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe demo.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

macOS / Linux：

```sh
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python demo.py
.venv/bin/python -m unittest discover -s tests -v
```

## 示例说明

`demo.py` 使用明确标注的合成图和合成金额，通过本仓库计算函数输出结果：

```text
原料 ──0.5──→ 加工 ──0.4──→ 终端
  └──0.3──→ 替代环节 ──0.8──┘

终端的最强路径暴露 = max(0.5 × 0.4, 0.3 × 0.8) = 0.24
EBIT = 利润总额 1.2 + 利息费用 0.3 = 1.5 亿元
利息保障倍数 = 1.5 / 0.3 = 5
```

这里的 0.24 不是预测概率。示例没有使用真实企业，没有运行完整信贷评分，也不产生比赛提交件。

## 从比赛工程中保留的取舍

- **系数与数据解耦**：路径函数接收调用方给出的图，不在算法内加载固化行业表或猜测节点别名。
- **聚合节点只作端点**：调用方可通过 `endpoint_only` 禁止跨越聚合代理，以免把两个子行业通过总量节点连成虚构链路。
- **出处跟随路径**：每条边的 `provenance`、`estimated` 随报告返回；没有给出年份时保留 `None`。
- **财务口径先于比值**：EBIT 使用利润总额加利息费用；净财务费用与利息费用不混用。
- **未知不写成零**：无图覆盖不代表无风险；零利息费用下的保障倍数无定义。
- **信用链不能凭行业共现编造**：企业事实关系消费尚未实现，传入事实边会明确抛出 `NotImplementedError`。

## 测试与范围

测试覆盖最强路径与路径和的区别、环路、跳数边界、聚合节点、来源标记、财务组成项冲突、缺失和非有限数，以及重复或不完整契约。

这份公开核心不等同于完整参赛系统。行业数据接入、全量风险特征、信贷策略、比赛数据与历史交付物没有包含在内。当前测试不能证明预测准确率、实际信贷收益或比赛排名。

传播路径只接受 `[0, 1]` 的有限边权，默认最多两跳，接口上限为 `MAX_HOPS = 8`，用于控制路径枚举规模；需要更大范围时应先评估图规模并修改该命名常量。聚合节点集合为空时不启用端点阻断规则。

财务模块保留原项目的显式历史兼容能力。新的调用使用 `allow_legacy=False, allow_missing=False`；流动性模块的历史年度口径回退由 `SUBSEQUENT_INCOMPLETE_FALLS_BACK_TO_ANNUAL` 控制，并在结果中标记依据，不能混同为后续时点的完整披露。

## 来源与许可

这是个人参赛项目的公开整理版本。财务、契约和缺失值模块保留来源快照；传播模块为解除行业数据耦合进行了适配，详见 [来源说明](docs/provenance.md)。
