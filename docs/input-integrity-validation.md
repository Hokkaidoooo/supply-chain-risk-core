# 0.3.1 输入一致性验证

日期：2026-10-15。

资本金额现在由 `credit/capital.py` 完整解析，工商特征和公开工作流共用该入口。`100人民币` 与 `100元人民币` 均为 0.01 万元人民币；`100英镑` 为 0.091 万元人民币，`100万英镑` 为 910 万元人民币。非法千分位、混合币种、溢出及下溢明确失败，合法未知继续使用原缺失语义。

换算使用独立 Decimal 上下文，调用方调整精度、舍入或指数范围不会改变结果。资本字段直接交给金额解析器，通用文本清洗不再删除数字之间的换行等字符。

财务记录由 `canonicalize_loss_history` 统一核对亏损年数。已知亏损年数和未知年份共同约束允许范围；三期原值齐全时可推导缺失年数。公开 JSON 的严格类型约束保留，DataFrame 内部的整数浮点表示和缺失值仍能正确处理。年度及净利润口径见 [输入契约](input-schema.md)。

## 实际验证

| 检查 | 结果 |
| --- | --- |
| 旧实现反例 | 首轮新增 12 个测试方法产生 60 个失败子用例，覆盖单位误算、错误语法和亏损声明矛盾 |
| 定向回归 | 最终 17 个测试通过，另覆盖 Decimal 上下文、删除式预清洗和 DataFrame 缺失表示 |
| 完整单测 | `python -B -m unittest discover -s tests`，75 项通过 |
| 代码检查 | `python -m ruff check --no-cache src tests tools` 通过 |
| 来源清单 | 29 个模块、1 个合成输入、19 件案例成品指纹一致 |
| 构建 | 0.3.1 的 sdist 和 wheel 均成功构建 |
| 安装后运行 | 安装 wheel 后从仓库外执行；确认导入来自隔离环境的 `site-packages`，完整演示及复算通过 |
| 原示例 | 新生成的 8 件输出与现有示例逐字节一致；只更新结果清单的版本、源码绑定和生成环境记录 |

`tests/test_credit_inputs.py` 包含三期利润的 27 种正、零、负组合。三期净利为 -1、-2、-3 却声明亏损 0 年时，完整工作流和直接财务特征入口均拒绝；声明为 3 时正常生成连续亏损规则命中。输入对象不被修改。

原合成输入、报告、图、比赛成品、评分权重和决策规则未改动。`turn_to_loss` 仍为来源声明的独立风险信号，本轮不据其推断转亏年度。这些测试证明输入处理与工程复现行为，不提供新的预测准确率证据。
