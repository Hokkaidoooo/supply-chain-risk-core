# 复现与结果核验

`risk-study demo` 使用包内合成输入，`risk-study run` 使用指定 JSON。两者都先计算，再在临时目录完整生成文件，最后写入一个新的结果目录；文件采用独占创建，清单最后落地。

结果包含输入、分析 JSON、Markdown、HTML、SVG，以及可选 Word 和 Excel。报告都读取同一分析结果，Office 文件使用固定的 ZIP 元数据及基准日属性，便于相同环境重复生成后比较字节。

`manifest.json` 记录输入指纹、全部 Python 模块的联合指纹、计算结果指纹、依赖版本和每个输出文件的哈希。`verify` 检查实际成员、大小、哈希与输入，然后调用当前代码真实重算并比较分析结果；启动命令成功不等于验证通过。

## 使用方法

```sh
python -m supply_chain_risk_core.cli demo --output output/run-01
python -m supply_chain_risk_core.cli verify output/run-01
```

命令行的标准输出和错误输出统一为 UTF-8，包括中文帮助、错误提示与结果路径，不依赖 Windows 的默认代码页或 `PYTHONIOENCODING`。作为 Python 库导入时不会修改调用者的标准流设置。

修改代码或输入后，请使用新的目录。源代码指纹改变时，旧结果会明确报告版本不匹配；历史结果仍应保留其对应代码。清单用于一致性核对，不是数字签名，也不能证明来源网址真实。

## 数值复算的比较范围

来源、输入、保存的分析及所有文件哈希始终严格核验。复算默认也严格比较结构、类型、顺序、业务结论和其他数值，仅对 `input_output.condition_number` 允许最多 32 个相邻双精度浮点表示的距离（ULP）。这是矩阵条件数这一诊断量的工程容限，不是所有后端或所有输入都能通过的保证；超过范围会明确失败。

例如已观察到不同 CI 环境分别给出 `2.777237851013947` 和 `2.7772378510139455`，相差 3 ULP，其他结果完全一致。比较不会舍入输入、原始计算值或哈希，也不改变矩阵病态判断。接受的微差会在命令返回的 `numerical_differences` 中列出字段、保存值、重算值、距离及限值；`recompute_policy` 明确标识采用的规则。

生成与核验使用同一策略；`run`、`demo` 和 `verify` 都可以加 `--exact-recompute` 关闭该容差，例如：

```sh
python -m supply_chain_risk_core.cli verify output/run-01 --exact-recompute
```

严格模式或超出允许范围时，错误包含首个差异字段及值，浮点值同时显示十六进制表示。清单本身不能扩大容差；策略与源码指纹一起绑定。

## 与原工程对照

持有本人原工程时，可以运行：

```powershell
python tools\compare_original.py --original-root '<原工程目录>'
```

工具会导入指定工程中的 Python 模块，只应指向自己信任的源码；它关闭字节码写入，使用合成输入进行对照。对照覆盖工商特征、评分、授信结果、规则常量、链投影和定量案例，不代表全部历史输入等价，也不重新生成比赛计分件。

## 可复核边界

一般单元测试与数值对照不需要比赛原件。历史决赛工作簿与讲解材料是独立保留的成品快照，不能用合成案例替代其原始输入来声称复现了真实比赛结果。
